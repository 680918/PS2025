# 原书阅读入口与加载恢复

用户反馈“阅读全书”只见“1 / 208 页，878字”的提取提示，翻页按钮出现禁止光标。本次核对到完整208页、44581899字节的PDF仍保存在本机。提取覆盖是Coach可引用的文字范围，不是用户能阅读的页数。

## 使用效果

“阅读全书”优先显示原始页面与阅读工具栏，无需先OCR。Coach文字依据收进默认折叠的说明，避免把识别范围误当作原书阅读限制。仍可连续滚动、跳页、放大；阅读不调用AI、不增加已讲解进度。

初次加载增加进度条和阶段说明；初始化失败会显示“重新加载原书”，该按钮在组件异步加载前就绑定。保留下载原件，另提供“直接打开原始PDF”，在浏览器支持的PDF阅读器中打开完整原件，不依赖本站PDF.js初始化或OCR。部分浏览器设置会将PDF交给下载或外部阅读器处理。

## 实现边界

PDF.js改用同一固定5.6.205版本的官方legacy兼容构建，主线程和worker配套，避免直接依赖所有浏览器都已有最新Map/Promise等能力。沿用原cmaps、字体、WASM与许可，本次仅新增2个兼容脚本并更新逐文件指纹，官方npm SHA512与原记录一致。不执行安装脚本。兼容构建不代表支持所有旧浏览器，仍需现代浏览器和JavaScript。

新增受原账户登录、本人归属、来源、指纹校验保护的`GET /web/materials/{id}/read/pdf`，仅接受PDF，不接受查询参数，与原下载共用限流和并发准备限制。返回`application/pdf`及`inline`，原下载仍为`application/octet-stream`和`attachment`。不开放匿名文件、不改账户或数据库结构、不增加Python依赖。

仅原PDF直开响应使用`object-src 'self'`以允许浏览器PDF组件；保留`default-src 'none'`、禁止框架嵌入、禁止表单、nosniff和不缓存。普通页面和下载原件的安全头不改。参见[MDN object-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/object-src)及[MDN sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)；强制CSP sandbox会禁止插件，不能用它阻断原生PDF阅读组件后仍宣称入口可用。
