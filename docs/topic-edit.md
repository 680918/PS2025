# 修改学习记录

从“我的学习”的每个主题卡片，或统一对话右侧当前主题的“修改学习记录”进入。可修改主题名称、已讨论内容与下一步，不必填写反馈评分或提交练习；预先显示原记录，只改需要调整的内容，取消不保存。标题1至120字，已讨论内容和下一步各1至800字。

修改不调用AI、不新增对话或AI受理次数。下次主动续学才会将修正后的当前记录交给已启用的AI；之后有新的实际讨论时，Coach仍可更新摘要和下一步。这不是固定目标锁定、完成标记或掌握程度评定。

保存保留主题编号、关联资料、当前选段、学习单元、讲解记录、历史消息、教案和引用。当前主题同步到统一对话输入框上方的紧凑状态；完整记录在“我的学习”查看。修改其他主题不会切换正在进行的主题或重温教案。改名后的历史对话按原主题编号仍能查到，原消息与教案正文、引用快照不回写。同一账户的规范化同名主题拒绝合并；不同账户同名互不影响。

多页面或AI回复已更新记录时，旧编辑页不能覆盖新值。显示当前保存记录并保留本次填写，由用户核对后再明确保存。版本比较包含完整记录与资料关联，避免同一秒内更新被漏过。正在回复时，修改保存暂缓且保留填写。登录、归属、同源、防伪、表单体量和请求次数沿用现有保护。

沿用现有SQLite表与事务，无数据库迁移、新依赖、自动调度或额外后台任务。旧学习导出使用最新记录；完整备份机制不变。

## 检验结果

最终源码完整隔离回归：2889 passed，1项既有Starlette/httpx弃用提示，613.46秒；未更换依赖。完整源码副本见本步骤check-manifest.json。

专项检验：最初25项通过、2处断言失败，原因为用不同时间比较每日额度倒计时、把实际来源编号误当成选段展示字段；更正后113 passed相关回归，85.46秒。

实际浏览器发现原生表单把多行提交为CRLF，导致控制字符校验拒绝。已统一换行，同时把记录版本核对放到字段校验之前，避免无效旧输入经纠正后跳过冲突确认。修复后28 passed专项，17.52秒；旧源码的未完成全量检查已停止，以修复后的完整源码重新检查，未将中断记录算作通过。

6个Python源文件与测试文件Ruff检查及格式检查通过。所有待提交源码、CSS和测试文件与最终全量源码副本哈希一致，无新增依赖或数据库迁移。

虚构8802浏览器：从统一对话右侧进入编辑；两页同时编辑，另一页先保存，旧页明确显示当前记录、保留多行填写，再明确提交后保存成功。修改清晰表达主题后，当前阅读主题与原书片段2仍保留；点击续学，模拟回复使用修正后的“阅读与实践”名称和下一步。演示服务重启后仍保留记录。无需填写评分，不自动调用AI。

桌面1280×900布局和320像素手机均已检验。手机编辑页clientWidth=scrollWidth=305，标题和两段正文输入左右边为37/268；手机统一对话同样无整页横向溢出，速览保留当前主题与原书片段。已保存桌面结果、手机表单和冲突页截图，并恢复默认视窗。

全部使用隔离源码、虚构账户、模拟回复，没有读取真实账户、对话、书籍、邮箱授权码或敏感配置，没有调用真实SMTP或计费AI，没有停止真实8785服务。真实AI在新讨论中整理摘要的质量仍由实际试用确认。
