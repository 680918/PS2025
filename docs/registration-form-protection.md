# 注册表单防伪提交保护

本说明记录注册表单的 CSRF 防护和浏览器上下文。后续已接上 [网页申请保存](registration-application-saving.md)：通过这些检查后会保存带归属的待验证申请及密码安全哈希，但不创建正式账户、不发邮件，也不建立登录会话。下述防伪规则继续适用。

## 用户看到的效果

- 从 `/web/register` 打开页面即可正常填写；新增的防伪字段不可见，无需用户额外操作。
- 有效期为 30 分钟。有效期内打开多个标签页或修改字段错误，可以继续使用同一个浏览器上下文；打开页面不会延长期限。
- 名称、邮箱或密码格式有误时，继续显示原有字段提示，名称与邮箱按原规则转义回填，密码始终为空。
- 没有有效表单、凭证过期或被篡改、其他浏览器的表单、跨站提交等，显示「请重新打开注册页面」，提供「重新打开注册页」按钮；不回显名称、邮箱、密码或防伪字段，不创建账户或发送邮件。
- 重新打开注册页可恢复。服务重启后也需重新打开页面，已填内容不会被服务端保存。

## 服务端规则

`api/registration_pages.py` 统一处理注册 GET 与只读 POST。GET 设置短期、服务端签名的 `coach_registration_form` Cookie，表单携带对应的随机隐藏字段。

- Cookie 使用 HttpOnly、SameSite=Strict、`Path=/web`，HTTPS 下加 Secure；本机 HTTP 仅用于本机开发。
- 签名绑定注册表单用途、随机字段和到期时间，不包含名称、邮箱或密码。密钥仅在本机进程内保存，服务重启后旧签名失效；公开多进程部署前需配置共享签名密钥并补部署测试。
- POST 先拒绝明确跨站来源，校验签名 Cookie，再有界解析表单，比较隐藏字段，之后才检查用户填写。兼容隐私浏览器的 `Origin: null`，但仍要求签名和隐藏字段同时正确；`Sec-Fetch-Site: cross-site` 始终拒绝。
- 请求最多 8192 字节、4 个唯一字段：`name`、`email`、`password`、`csrf`；重复或额外字段、编码错误、其他内容类型返回不回显内容的 400 HTML。防伪检查失败返回 403 HTML；格式校验通过仍返回诚实的邮箱验证准备页。
- GET、字段纠错页、准备页和恢复提示页均禁用缓存与 Referer，限制外部资源、嵌入和表单目标。Cookie 不是登录凭证、邮件验证凭证或注册申请编号，不写入数据库。
- 这些表单凭证在有效期内可以重复用于填写检查，不能将它们视为一次性邮件链接或重复申请的业务防护。后续保存申请仍须遵守已有申请不可覆盖的事务规则。

防伪字段与邮箱确认 Cookie 各自独立，不能互换。本步不修改已有确认链接的有效期或一次性语义。

## 范围与后续

本步保护新的 `POST /web/auth/register`。此前仅登记姓名、邮箱的开发用 `POST /web/register` 仍保留供旧开发流程使用，不属于正式注册入口；本机产品仍不可公开部署。后续公开前需关闭或保护旧入口，并完成请求次数限制、申请保存与浏览器归属关联、重发与发信失败恢复、真实 SMTP 接入及登录。

注册预览的 [请求次数限制](registration-rate-limits.md) 已接上，超限在解析请求和字段校验前返回稍后重试提示；本步的防伪凭证检查继续保留。后续再补浏览器与申请归属关联，并连接申请保存、重发与失败恢复。

## 验收

```powershell
python -m pytest tests/test_registration_form.py tests/test_pending_registration.py tests/test_web_registration_verification.py tests/test_password_credentials.py tests/test_email_verification.py -q -p no:cacheprovider
```

使用临时数据库和测试资料，禁止 SMTP。覆盖合法提交、跨站、缺少或篡改凭证、过期边界、多标签页、字段纠错、服务重启、恢复、HTTPS Cookie 属性、与邮箱确认凭证不可互换、密码不回显和真实数据不写入。浏览器另检查正常填写、拒绝后的恢复以及桌面与手机提示页排版。
