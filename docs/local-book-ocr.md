# 扫描书逐页本地文字识别

已新增[每批最多5页的小范围连续识别](ocr-page-range.md)：选定文件页范围后依次处理，仍需逐页核对保存，保留原单页入口。下文保留单页功能和数据边界说明。

## 使用流程

在“阅读全书”定位到缺少正文的PDF文件页，点击工具栏“识别当前页”。页面在本机浏览器中将原页渲染为图像，用本地部署的Tesseract识别，不向外部OCR服务发送书页，不调用付费AI。可选择“简体中文+英文”或“繁体中文+英文”。

结果先留在可修改的文字框中，显示识别页码和机器置信度。置信度不是准确率保证，更不是学习评分。核对原页、修改错字或段落顺序后，明确点击“核对无误，保存此页文字”。只有保存后，文字才加入该书的可引用片段。随后点击“选段学习这页文字”，在统一聊天框明确提问或讲解。

本次是逐页识别，不是自动识别整本书。优先适配清晰横排文字；竖排古籍、表格、特殊字体、模糊和倾斜扫描可能不准，识别结果需要核对。一次最多处理500万像素，识别最多等待90秒，支持取消；运行速度取决于本机，第一次准备组件和模型会慢一些。

未保存的结果不会改写书籍，浏览器离开时会提醒；保存前可放弃重做。识别期间可以继续阅读，结果和保存始终绑定开始识别时的真实文件页，不随滚动改变。

## 数据保留与边界

- 原始PDF、原件指纹、标题和文件页数不变。已有文字页面不重复识别入库，不覆盖原生文字或已保存OCR文字；重复或并发保存只允许一次成功。
- 已有片段UUID、引用定位字符串、正文、学习位置与讲解记录保留。新增片段按实际PDF页排序，旧UUID不变；数字片段索引会随新页插入调整，历史引用按UUID核对，旧引用快照保留。
- OCR新增文字每页最多4万字，整书已提取文字合计仍最多200万字；增加的是资料的可引用文字量，不重复占用原件存储额度。
- 同一本书复查OCR结果时可以调阅已保存文字，但本阶段不直接覆盖它，避免改动旧引用。需要修正时，先在保存前充分核对。片段预览明确标注OCR来源；引文仍应回到PDF原页核对。
- OCR与保存不调用Coach、不计入AI受理；选择片段也不调用AI，后续明确讲解才调用。识别文字仍是非可信资料，不能作为指示Agent改规则的系统命令。
- 新增`material_ocr_pages`用于记录经确认的文件页、机器置信度、识别方式和保存时间，其他表结构不改。新旧资料库启动时可幂等增加该表，旧数据不重写。
- 原件及ZIP中的“原始资料”仍是最初PDF，不自动嵌入OCR层。OCR确认记录与片段随现有本机整库备份保留，可恢复；后续从这些文字整理并确认的教案，仍按现有方式导出。文字也可以在核对框中复制留存。

## 本地组件与供应链

固定Tesseract.js 7.0.0与Tesseract.js-core 7.0.0，模型来自官方tessdata_fast提交`87416418657359cb625c412a48b6e1d6d41c29bd`。简体、繁体和英文模型均保存在本站静态目录，按需加载。包括兼容的WASM核心及许可文件约50MB，这是开发分发资源体积，不是每识别一页增加50MB，也不计作用户上传原件容量。

包从官方npm下载并校验SHA512，模型按官方Git对象哈希校验，文件SHA256、来源及许可保留在`PROVENANCE.json`。不执行npm安装脚本，不新增Python依赖或GPU要求。Git保留上游字节，许可证原文保持完整。

客户端明确指定本站worker、core、lang路径和非Blob worker，不依赖外部CDN。参考[官方本地部署说明](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md)、[Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)和[官方模型仓库](https://github.com/tesseract-ocr/tessdata_fast)。

页面接口按账户与原书校验，保存还核对来源、会话防伪、PDF指纹、页码、正文长度、置信度和总字数；事务内再检查已有文字，拒绝覆盖和重复计量。只处理用户明确提交的核对文字，不在后台自动识别或自动发送给模型。
