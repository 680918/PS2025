# 网页保存待验证申请

本步将已有防伪、限流和归属绑定连接到注册网页。提交测试资料后会保存邮箱、称呼和 Argon2id 密码哈希，并交给发起申请的浏览器专用归属 Cookie；不保存原始密码，不创建正式账户，不签发或发送验证邮件，不开放登录。

## 用户流程

1. 打开 `/web/register`，页面说明这是本机测试，提交会保存待验证申请，请使用测试资料。
2. 点击「保存申请并继续」，服务端先检查请求额度、来源、防伪凭证和字段格式。
3. 校验通过后原子保存申请、密码哈希和浏览器归属摘要。成功以 303 跳转至 `/web/register/pending`，凭证不进入 URL 或 HTML。
4. 等待页显示「申请已保存，等待验证邮箱」、部分遮盖的邮箱、北京时间到期时刻，以及「邮件尚未接通，无需等待邮件」。不会声称账户已创建或邮件已发送。
5. 刷新等待页只查询归属和状态，不重复保存、不延长期限。有效申请默认 1 小时到期。

同一浏览器已持有有效申请时，重复提交只回到原申请，不重新哈希，不更改已保存的邮箱、称呼、密码或到期时间。当前未提供修改、取消或转移申请功能；等待页明确说明重复提交不会修改原内容。

另一浏览器不能仅凭邮箱、编号或错误凭证查询、重绑或覆盖申请。重复邮箱、已有账户或其他不可用情况统一显示无法继续，不公开具体邮箱状态。丢失归属 Cookie 后不能仅凭邮箱认领原申请；申请恢复另行设计。

## Cookie 和请求保护

- `coach_registration_form` 继续用于 30 分钟的表单防伪保护。
- 新增 `coach_registration_application`，内容为申请编号与独立随机凭证，只通过 HttpOnly Cookie 交给浏览器，使用 SameSite=Strict、`Path=/web`，HTTPS 下设置 Secure。最大有效期不超过原申请剩余时间。
- 原始归属凭证、完整邮箱、密码和密码哈希不进入等待页、链接或日志；Cookie 不是登录会话，也不能代替邮件验证。
- 服务重启后数据库中的申请归属仍有效，等待页可以继续查询；提交新表单前须重新打开注册页获取新的防伪凭证。
- 已完成、过期或归属无效时显示通用提示并清除失效 Cookie，不泄露其他申请的信息。邮箱确认仍可在另一浏览器完成；之后旧等待页不可用。
- GET 注册页、GET 等待页分别使用每来源 30 次、服务进程 240 次的滚动 60 秒额度；POST 仍为每来源 10 次、进程 120 次。两类 GET 独立，避免合法保存后的状态跳转被注册页浏览额度挡住。
- 所有页面和重定向使用 no-store、no-referrer 与现有 CSP。HTTP 表单仍最多 8192 字节、4 个唯一字段，不新增公开签发、重发或登录接口。

## 稳定性与错误处理

密码哈希通过工作线程执行，单个应用实例最多同时处理 2 份新申请，不无限排队。忙碌时返回 503 与 `Retry-After: 2`，用户稍后重新填写即可。申请保存始终在此前完成 CSRF、频率及格式校验之后执行。

已有有效归属时先查询并复用申请，避免重复计算。并发首次提交依然受数据库唯一约束保护，只有一份申请成功；另一份不能替换其内容。

保存事务包括申请和归属，失败全部回退，不设置新的归属 Cookie。申请不可用统一返回 409；SQLite 运行故障返回不暴露细节的 503。状态查询故障保留已有归属，不假装申请丢失，也不另建申请。成功提交后若网络中断导致 Cookie 未收到，不得仅凭编号重新认领；后续需通过明确的恢复流程处理。

## 当前边界

仅供本机验收。网页现在会保存待验证申请，正式用户表和正式密码表只在后续有效邮件确认时写入。申请保存不会调用 SMTP、模型或其他外部服务；邮件链接仍仅可由受信任内部流程生成。

旧开发用 `POST /web/register` 尚未关闭或保护，其他公开部署准备也未完成，不能将当前项目对公网开放。下一小步建议先记录首次发信的准备、成功与失败状态，保证重试和页面提示不误报，再接入真实发信。

## 验收

```powershell
python -m pytest tests/test_web_registration_application.py tests/test_registration_form.py tests/test_registration_rate_limit.py tests/test_registration_browser_binding.py tests/test_web_registration_verification.py -q -p no:cacheprovider
```

测试只使用临时数据库及测试资料，禁止 SMTP。覆盖成功保存与跳转、Cookie 属性、密码不回显与不落明文、刷新与重复提交不改写、错误凭证、过期、重启、匿名重复与旧账户保护、保存和查询故障、哈希并发上限、并发同邮箱竞争及内部邮件确认后的失效。

浏览器验收检查正常填写、刷新等待页、换浏览器或凭证失效的提示、桌面和手机排版，并核对临时数据库中只有申请、归属和密码哈希，没有正式用户或已签发邮件。
