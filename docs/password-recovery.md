# 邮箱找回密码

从登录页“忘记密码？通过邮箱找回”进入。填写注册邮箱后主动申请邮件；请求页面统一提示“若邮箱已注册并完成验证，且邮件投递成功，请查收”，不透露地址是否注册。点击最新邮件中的链接，填写两次新密码，确认后重新登录。学习记录、原始资料和教案仍关联原账户，不新建或迁移账户。

## 账户与邮件边界

- 仅可重置已有密码、邮箱已验证且仍与账户当前邮箱一致的账户。不会借找回流程激活旧账户或创建新账户。
- 32 字节安全随机链接，30 分钟有效，按用途加前缀后取 SHA-256，数据库只存摘要。每个账户保留一个最新链接；重新发送使旧链接失效。服务重启后链接及每账户 60 秒冷却仍保留。
- 打开邮件链接只检查，不消耗链接。浏览器获得短期 HttpOnly、防伪签名的上下文后重定向到无 token 的表单地址。新密码只在 POST 提交，不在 HTML、URL、日志或邮件中回显。
- 新密码规则与注册一致：15–128 字符，可使用中文和空格；两次必须一致。Argon2id 安全哈希。实际提交时再次检查有效期、邮箱和链接，在同一事务更新密码、撤销该账户全部登录会话并删除重置链接；失败回滚。登录保存会话时再次检查所验证的密码哈希，防止与重置并发的旧密码登录建立新会话。
- 重置不自动登录。邮件已启用时，成功后尝试发送密码更改通知；通知不含密码，也不附带登录凭证。通知失败不会回滚密码，投递没有自动重试或持久队列。

## 投递与页面反馈

邮件和账户查询在通用申请响应送出后执行，避免 SMTP 时延透露注册状态。最多两个邮件任务；每来源每分钟 3 次申请、应用每分钟 30 次；同一邮箱每分钟 1 次（包括不存在的邮箱），不采信转发来源头。当前运行器只面向本机单进程，公开部署前需重新评估限流、发件服务、可观测性与任务可靠性。

未配置邮件、服务忙、请求过频、表单过期、链接失效、两次密码不一致均有明确提示。页面提交期间显示动态等待标识并禁止重复点击，保留无 JavaScript 的表单流程。网络中断不自动重试，提示先查收邮件或尝试新密码登录。不存在的账户、未验证账户、收件范围不允许和 SMTP 失败都使用同一申请结果；“没有收到邮件？”展开说明包含投递失败及主动重试办法，不将邮件请求等同于已送达。投递结果不确定时保留链接可用，避免服务器已收信后链接被意外撤销。

## 本机试用

默认 `--ai` 不开启发信。原来的 `--register` 现在同时开启本人 163 邮箱注册、找回密码和重置通知，仍在终端隐藏输入授权码，仅在本次进程内使用，不写文件，不经聊天传递：

```powershell
Set-Location 'D:\Personal-Growth-Coach'
& 'C:\BCtools\anaconda3\python.exe' -m api.coach_run --ai --register --port 8785
```

在旧服务窗口按 Ctrl+C 后再用同一端口启动。使用原来的本人注册邮箱；不需要重新注册。只有网页主动申请、确认重置会触发相应邮件。

模拟模式可用虚构账户注册、模拟验证后找回，申请完成页提供“查看本浏览器的模拟重置邮件”。模拟收件箱只在显式模拟邮件配置下存在，按当前浏览器签名上下文显示最新重置链接；真实模式无此入口。自动检验不访问真实账户或学习内容，不连接真实 SMTP 或 AI。

实现参考 [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。这是本机试用流程完善，不代表公开商用部署已经完成。

## 检验结果

2395 项全量回归通过（278.60 秒）；最终表单输入框排版调整后，37 项密码找回专项检验通过（17.24 秒）。Ruff 检查和格式检验、JavaScript 语法检查通过。自动检验覆盖一次性链接、精确过期、重启后的冷却、邮箱归属、并发消费与回滚、旧密码并发登录、旧会话撤销、其他账户隔离，以及重置前后学习主题、聊天、已保存教案与原始资料数据库哈希一致。浏览器检查登录入口、模拟邮件申请、仅当前浏览器可见的模拟链接、无 token 表单地址与过期上下文提示；最终桌面输入框与新密码表单排版已查看，320 像素手机页面无横向溢出，输入框和按钮均在卡片内。浏览器未填写或提交新密码；重置成功及新旧密码重新登录由隔离自动检验完成。未访问真实账户或资料，未连接真实 SMTP 或 AI；真实 163 收信和本人新密码输入留给本人在页面体验。

## 邮件按钮跨站跳转修正与阶段保存

本人已反馈真实 163 邮件能够收到，但从邮箱按钮打开新标签后没有新密码表单，复制地址打开则正常。开发在两个不同本机站点使用同一封虚构邮件复现：Strict 重置上下文在跨站重定向中未携带，页面误报失效。仅将短期、签名的重置上下文改为显式 SameSite=Lax，保留 HttpOnly、HTTPS Secure、用途绑定、一次性链接、同源 POST 与浏览器绑定 CSRF；登录和找回申请 Cookie 仍为 Strict。修正后从同一邮件按钮打开新标签，已直接显示两个可编辑密码输入框，干净地址不含 token；浏览器未输入新密码。新增跨站表单保护检验后，90 项相关回归通过（33.80 秒），静态与格式检查通过。此前 2395 项全量回归记录保留。本轮仍未访问真实账户、邮箱凭据或学习资料，也未发送真实邮件。用户已明确要求修复后继续下一步，按该确认保存本阶段实现；修正后的真实 163 点击体验尚待本人复查。
