# 开发与交付方式（2026-10-18 起）

用户已明确调整开发授权：按照已确认产品蓝图自主安排优先级，连续推进常规开发、检验、修复和必要文档，检验通过后直接 commit 并推送现有开发分支，不再每一步等待方案确认或体验验收。

保持适中的功能粒度和可追溯提交。阶段汇报说明完成内容、检验、体验入口及实际限制；界面和交互细节集中收集后调整，影响账户、资料保存和数据安全的问题及时修复。既有文档中的逐步确认属于当时流程，后续以本文件及最新项目状态为准。

必须用户本人操作的账号、验证码、付费开通，或确实缺少信息的关键事项，明确说明需要用户做什么和原因。普通实现选择、可逆修复和已授权范围内的提交同步由开发代理直接落实。

真实账户、授权码、聊天和原书不作为自动检验数据；常规检验使用隔离源码、虚构账户及模拟回复。真实 AI 质量、真实邮件和公开商用条件分别据实记录，不把模拟检验写成真实效果验收。保持敏感配置和业务数据与源码提交分离。
