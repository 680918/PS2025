# 已保存教案的持续修订

左侧“知识资产沉淀 → 已保存的教案目录”打开教案，可选择“修改教案”或“版本记录”。修改页预填标题和正文，保存后回到阅读页，显示当前版本与修订时间。标题最多 120 字、正文最多 12000 字，支持原有安全 Markdown 阅读排版；取消返回不会保存，未保存的编辑不自动留存。

第一次修订保留原版，以后每次明确保存新增一版；未改动内容不重复建立版本。版本记录每页 20 项，可查看完整历史正文。恢复旧版需在旧版阅读页明确确认，以旧版标题和正文建立新的当前版本；后来的版本仍保留，恢复成相同内容不建立重复版本。

版本记录使用原对话数据库新增表。既有教案无需重新生成，在首次编辑时留存原文。当前标题和正文、历史原版、新版本在同一事务内保存，失败整体回滚；主题、初次保存时间、来源和原始资料不变。旧页面提交时若已有新版，返回冲突提示，保留本次未保存的标题和正文，同时可展开当前内容进行核对；重新保存需用户再次明确操作。防伪凭证绑定登录会话、教案、基础版本，恢复还绑定目标版本；所有查询和写入按登录账户隔离。

正在重温的教案在本轮 Coach 回复完成后才可修订或恢复，避免回复引用与正在编辑的内容混淆。历史交流中的文字不改写，新的重温请求读取当前版本。修改、查看和恢复版本不调用 AI、不发送邮件；版本记录只增加标题、正文和少量元数据，不重复存储书籍和引用片段。版本不会自动裁剪删除，磁盘占用随人工修订次数增长，未更改的内容不新增记录。

单篇下载、查找和打包导出使用当前标题与正文；导出包仍是当前内容的阅读副本，本轮不含历史版本打包。原有引用仅作为“整理时参考”，不表示用户新增的文字已由原书核实。恢复版本、手动编辑不会自动生成新引用，也不会让模型自动修改已保存教案。

本轮只做手动修订与版本留存，不引入新的服务或通用版本框架。开发检验使用隔离源码与虚构账户，不访问真实账户、邮箱授权码、聊天或书籍，不调用真实 SMTP 或计费 AI。本阶段实现与检验已完成，用户确认继续下一步，按该确认保存至开发分支；真实 AI 的讲解质量仍需本人持续体验。

## 本机体验

按原方式重启 `python -m api.coach_run --ai --port 8785` 后，用原账户打开一份已保存教案，依次试“修改 → 保存 → 版本记录 → 阅读旧版 → 明确恢复 → 再重温或导出”。无需重新注册，也无需 163 授权码；仅编辑和管理版本可以不启用 AI。

重温、阅读或解释教案时，不会仅因出现“教案”二字就请求生成新草稿；明确要求重新整理仍沿用原有草稿确认流程。历史回复不改写。

## 检验结果

2488 项全量回归通过（344.97 秒）；最终修正重温教案被误判为生成草稿后，128 项相关回归通过（54.79 秒）。Ruff 检查与格式检验通过，未新增依赖。检验覆盖既有教案兼容与原行保留、首次原稿留存、修订和恢复、同内容去重、旧页面重放、并发保存冲突、事务回滚、账户与会话隔离、防伪及来源校验、异常输入、正在重温时的保存保护、版本分页、当前标题查找，以及 AI 重温上下文和单篇/打包导出读取当前内容。浏览器在虚构账户中实际完成修改保存、两个页面冲突时保留填写并展开当前内容、取消不覆盖、阅读旧版、恢复第一版成为第三版且第二版仍保留、回到统一对话重温当前正文。发现原有规则将“请重温这份教案”误判为新草稿，已做最小修正并验证最终回复不再出现未生成草稿提示，明确要求重新整理仍支持。桌面和 320 像素手机已检查：手机页面内容宽度 305 像素，版本卡片左右为 18/287，编辑输入框和保存按钮为 35/270，无整页横向溢出。所有开发检验均使用隔离源码、虚构账户和模拟回复，未读取或修改真实账户、邮箱授权码、聊天和书籍，未调用真实 SMTP 或计费 AI。保留既有 Starlette/httpx 弃用提示；真实 AI 的讲解质量仍由本人体验。
