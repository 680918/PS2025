# 注册填写检查与邮箱验证准备页

最初的只读填写预览现已接上 [待验证申请保存](registration-application-saving.md)。网页会保存邮箱、称呼、密码安全哈希与申请归属，不创建正式账号、不发送验证邮件、不建立登录会话。仍处于本机测试阶段，请使用测试邮箱和测试密码。

## 页面行为

- `/web/register` 可以填写选填称呼、邮箱、密码；按钮为「保存申请并继续」。浏览器进行必填、邮箱类型、长度检查，服务端仍独立校验。
- 已增加不可见的防伪字段与短期浏览器确认信息，正常填写无需额外操作。表单过期、凭证不匹配或跨站提交时，提示重新打开注册页；详见 [注册表单防伪提交保护](registration-form-protection.md)。
- 称呼最多 40 个字符；邮箱按当前项目惯例去除两侧空白并转为小写，支持常见 ASCII 邮箱，拒绝多地址、显示姓名、控制字符及明显错误的域名。邮箱格式通过不代表邮箱已经存在或归本人所有，仍需后续邮件验证。
- 密码沿用既有的 15–128 字符要求，支持中文、空格与粘贴，拒绝全空白；不会去除密码两侧空格，通过校验后只保存 Argon2id 哈希，不保存原始密码。
- 出错时显示字段提示和可跳转的错误摘要；称呼和邮箱在可保留时回填并转义，密码始终为空，不进入响应、链接、Cookie 或日志。
- 填写通过后保存带归属的申请，303 跳转至等待页，邮箱部分遮盖。页面明确说明申请已保存、到期时间、「尚未发送邮件、未创建账户、无需等待邮件」，没有虚假的重发按钮；刷新不重复保存。

## 实现边界

`POST /web/auth/register` 要求有效的签名浏览器 Cookie 和对应隐藏防伪字段，只接受最多 8192 字节的 URL 编码表单。名称、邮箱、密码与防伪字段最多共 4 个唯一字段；重复字段、额外字段、错误编码、其他内容类型均返回不回显输入的 HTML 提示。防伪检查失败返回 403；格式错误返回 400，保存成功返回 303 并跳转到 200 等待页。注册 GET、提交与跳转响应均禁用缓存和 Referer，并限制页面资源、嵌入和表单目标。

已有账户和其他浏览器的有效申请不能被覆盖或重新认领，相关冲突统一提示暂时无法继续，不公开具体邮箱状态。同一浏览器已有申请时只回到原等待页，不改变原邮箱或密码。原登录页和登录提交保持未开放状态。此前的开发用 `POST /web/register` 仍保留，不属于正式邮箱注册入口；产品尚不能向公众开放。

未验证申请保存、归属、请求次数限制、CSRF 和确认后原子开户已接上。真实发信前还需补发信状态、重发入口和失败恢复，当前不能作为可公开使用的完整注册系统。

## 验收

```powershell
python -m pytest tests/test_registration_form.py tests/test_web_public_pages.py tests/test_password_credentials.py tests/test_email_verification.py -q -p no:cacheprovider
```

检查正常流程、字段边界、异常表单、转义和密码不回显、已有账号不可被修改、数据库不写入和不触发 SMTP。浏览器另检查电脑与手机窄屏排版。
