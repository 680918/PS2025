# 注册填写检查与邮箱验证准备页

本步接通网页表单的只读校验，不创建正式账号、不保存邮箱或密码、不发送验证邮件、不建立登录会话。注册流程仍处于本机预览阶段，请使用测试邮箱和测试密码。

## 页面行为

- `/web/register` 可以填写选填称呼、邮箱、密码；按钮为「检查填写并继续」。浏览器进行必填、邮箱类型、长度检查，服务端仍独立校验。
- 称呼最多 40 个字符；邮箱按当前项目惯例去除两侧空白并转为小写，支持常见 ASCII 邮箱，拒绝多地址、显示姓名、控制字符及明显错误的域名。邮箱格式通过不代表邮箱已经存在或归本人所有，仍需后续邮件验证。
- 密码沿用既有的 15–128 字符要求，支持中文、空格与粘贴，拒绝全空白；不会去除密码两侧空格，不执行哈希或保存。
- 出错时显示字段提示和可跳转的错误摘要；称呼和邮箱在可保留时回填并转义，密码始终为空，不进入响应、链接、Cookie 或日志。
- 填写通过后显示邮箱验证准备页，邮箱部分遮盖。页面明确说明「尚未发送邮件、未创建账户、无需等待邮件」，没有虚假的重发按钮。

## 实现边界

`POST /web/auth/register` 只接受最多 8192 字节的 URL 编码表单；重复字段、额外字段、错误编码、其他内容类型均返回不回显输入的 HTML 提示。字段错误返回 400，校验通过返回 200。所有提交响应禁用缓存和 Referer，并限制页面资源、嵌入和表单目标。

本步不查询某个邮箱是否注册，已有账户和新邮箱同样只经过格式检查，不改变原密码、验证状态或学习资料。原登录页和登录提交保持未开放状态。此前的开发用 `POST /web/register` 仍保留，不属于正式邮箱注册入口；产品尚不能向公众开放。

下一步接入真实建号和发信前，需要先定义未验证申请、邮箱所有权确认与密码写入的边界，并补齐 CSRF、请求额度限制、重复申请和失败恢复。本步的只读校验不能直接当作可公开使用的注册接口。

```powershell
python -m pytest tests/test_registration_form.py tests/test_web_public_pages.py tests/test_password_credentials.py tests/test_email_verification.py -q -p no:cacheprovider
```
