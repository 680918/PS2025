# 待验证注册申请基础

本步只提供受信任内部流程使用的保存与读取能力，尚未连接网页、SMTP 或正式账号创建。网页仍只检查填写，不保存注册申请。请勿把内部函数直接暴露为公开注册接口。

## 已完成的行为

- 先复用注册字段校验，再用既有 Argon2id 参数生成密码哈希。数据库保存哈希，不保存原始密码；密码两侧空格保留。未填称呼时使用「成长者」。
- 申请有独立的随机编号和 1 小时有效期。读取不会延长期限；到期后不可使用，在后续成功新建或读取有效格式编号的内部调用中清理过期记录，无后台调度。
- 同一邮箱只允许一份尚有效的申请。重复或并发提交不能替换申请编号、称呼、密码哈希或到期时间。过期后可重新申请，获得新编号和新哈希。
- 已存在的账户不允许被待验证申请覆盖；比较邮箱时考虑原有记录的大小写和两侧空格。申请存在期间若其他流程创建了该邮箱的账户，后续读取会清除这份失效申请。
- 所有操作都不修改正式用户、正式密码、已验证状态、学习或对话记录。申请编号不能充当用户身份、邮箱验证凭证或登录凭证。

## 内部接口

`security/pending_registration.py`：

- `begin_pending_registration(repository, *, email, password, name="", now=None)`：返回只包含申请编号和到期时间的 `PendingRegistrationReceipt`。现有账户或有效重复申请统一抛出 `PendingRegistrationUnavailable`，不将具体邮箱状态提供给网页。
- `get_pending_registration(repository, request_id, now=None)`：受信任调用者可读取内部申请记录；未知、过期、格式错误、尚未到创建时间或已被正式账户占用时不可用。

`now` 只供内部时钟和测试，必须包含时区，不得接收网页传入的时间。服务入口还需在接到公开请求之前实现请求额度限制。

内部记录包含邮箱和密码哈希，不能通过 HTTP、日志、`dataclasses.asdict` 或其他序列化输出。对象的默认 `repr` 隐藏这些字段和申请编号；这不等于允许任意序列化。读取成功也不代表已经证明邮箱归属。

## 数据位置与兼容

在既有 `users.db` 中新增 `pending_registrations` 表，使用参数化 SQL 与事务。保留原有用户、密码和邮箱验证表的字段、编号及数据。后续初始化仓库时按既有方式补建表，本次开发不手工运行真实数据库迁移。

新建与读取使用显式关闭的数据库连接。尚有效申请不更新；相同邮箱的竞争请求只允许一份成功。

## 下一步边界

旧的邮箱验证凭证关联已经存在的用户，不能直接把待验证申请编号传入该流程来建号。后续需要把新申请与一次性邮箱凭证绑定，确认邮箱归属后在事务中创建正式用户、写入对应密码哈希，再清除申请；同时完成 CSRF、请求次数限制、失败恢复与重发规则。

本步不创建新的 HTTP 接口、不发邮件、不开放登录，也不增加队列或定时任务。
