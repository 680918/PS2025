# 教案重温与结束重温

在已保存教案点击“在对话中重温”，仍回到同一个聊天框。原来已有的同名学习主题保留进度、下一步、书籍和选段，不再用“准备重温”覆盖已有学习记录；其他主题的位置也保留。若该教案主题尚不存在，沿用既有行为建立对应主题。

重温时左侧显示当前教案和“结束重温，继续主题学习”；手机速览也显示教案名称。右侧显示教案整理时保留的引用快照，不把主题原选段混作本次教案来源。继续按钮明确为“继续重温教案”。点击结束后，当前教案主题的原学习记录和选段重新用于主题学习；不会自动跳回进入重温前的另一个主题，其他主题仍可从“我的学习”选择。

重温请求提供当前已保存教案的正文与原始引用快照，不重新检索主题原书选段。模型对主题进度的更新在重温期间不写入，避免覆盖原学习位置。用户自愿修改学习记录仍保留。明确选择原书选段讲解或切换主题会离开重温，继续沿用原学习入口；教案再整理仍需确认保存。引用快照不代表已核实当前原书或通读全书。

本步保护后续重温，不猜测回填以前已被旧流程覆盖的学习记录；历史记录需要时可从“修改学习记录”自行核对修正。已有同名主题的书籍归属保持原样，教案可以引用另一份原书的整理快照，两者不会互相替换。

结束和浏览不调用AI；主动发送、继续重温或整理草稿仍走原有受理次数与AI调用，不另加一次请求。回复期间不能切换或结束重温。新增每账户的重温操作版本，既有重温记录没有版本时按0读取；反复选择同一教案也推进版本，旧退出表单不能结束新的重温。

网页对话表单绑定所见重温状态，在消息受理事务里核对。旧页面在进入、退出或更换重温后发送会被拒绝，不新增消息或AI次数。原有内部调用可不提供网页状态；原主题和选段绑定仍生效。所有页面按账户、会话、用途及同源校验，操作与状态写入在事务中完成。版本表随本机整库备份保留，不新增外部服务或依赖。

开发只使用隔离源码、虚构账户、原书片段和模拟回复；不访问真实账户或敏感配置，不调用真实邮件或AI，不停止原8785服务。
