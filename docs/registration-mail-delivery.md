# 注册邮件发送状态与失败重试保护

本步骤增加内部同步发送函数 `security.registration_delivery.send_registration_verification` 和持久状态，尚未接入网页。网页仍只保存申请，等待页仍显示尚未发信。测试仅使用模拟发信，不读取真实邮箱配置、不联系 SMTP，也不改动真实数据库。

## 状态与重试规则

| 状态 | 含义 | 本步骤允许再发送吗 |
| --- | --- | --- |
| `not_sent` | 归属有效，尚无受管理的发送记录 | 可以首次发送 |
| `sending` | 已在数据库占用本次发送，正在等待结果，或进程中途退出 | 不允许；不能凭等待时间推定失败 |
| `accepted` | 发信函数确认邮件服务器已接收 | 不允许；不代表到达收件箱 |
| `failed` | 已确认未成功提交，例如认证失败或服务器明确拒绝 | 只允许主动指定 `retry_failed=True`，距上次准备链接至少 60 秒 |
| `unknown` | 超时、连接中断、TLS 错误或其他不能确定是否已提交的异常 | 不允许自动或主动重发；保留可能已投递的链接 |

未启用配置在占用发送前拒绝，保持 `not_sent`；构建邮件的校验失败发生在连接 SMTP 前，记录 `failed`。TLS 错误采取保守规则，因为中断可能发生在提交邮件期间。后续若要增加“已接收但未收到”的主动重发，以及不确定状态的人工处理，需要单独设计，不能放开此处的保护。

## 数据与事务

- 新表 `registration_mail_deliveries` 每份申请只保留最近一次发送编号和状态，关联原申请并级联删除。没有新的账户、明文口令、邮箱授权码、明文浏览器凭证、完整链接或原始 SMTP 错误。
- 申请归属、有效期、已有用户冲突、冷却期、旧发送状态检查，以及链接摘要和 `sending` 状态的写入，处于同一个 `BEGIN IMMEDIATE` 事务。并发调用只有一个能够占用发送；事务失败回滚链接和状态，且不发送。
- 网络发送在事务提交后执行，等待 SMTP 时不持有数据库写锁。没有定时器、后台队列或自动重试。
- 完成结果必须匹配本次发送编号和原 `sending` 状态。旧调用不能覆盖新尝试；旧的链接签发函数也不能绕过受管理的发送记录改写链接。
- 若服务器已经接收，但最终数据库写入失败，函数返回 `unknown`，数据库保留 `sending`（或申请已被成功验证而删除）。重启、刷新和重新调用都不能触发重复发送；现有有效链接仍可确认。
- 有效期仍受原申请 1 小时限制，失败重试不续期。验证成功后仍由原有一次性原子流程创建账户，级联移除申请、归属、链接和发送状态；不自动登录。
- 状态查询必须有申请编号和正确浏览器凭证，只返回状态，不返回地址、链接、发送编号或密码信息。尚无公开的状态查询或发信接口。

## 检验

`tests/test_registration_delivery.py` 用临时 SQLite 数据库和模拟发信，覆盖首次发送、明确失败和冷却期、结果不确定、并发与进程中断、结果落库失败、事务回滚、越权、旧签发绕过、失效清理、隐私和确认开户。现有 SMTP 传输、注册及网页相关测试继续回归。真实投递另需用户同意后进行人工收信验收。

## 后续最小一步

在本机等待页显示上述状态，并设计首次发信与明确失败重试的受保护操作；明确呈现服务器接收与收件箱到达的区别。先使用模拟发信做网页验收，再安排一次真实邮件验证。正式登录、找回密码、公开部署仍未开放，旧开发注册入口仍需在公开前关闭或保护。
